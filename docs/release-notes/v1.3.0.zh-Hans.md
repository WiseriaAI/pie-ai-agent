# v1.3.0 — 支持更多浏览器，长任务更省

本次更新让 Pie 在侧边栏始终不显示的 Chromium 浏览器（最典型的是 Arc）上正常工作；通过让模型的提示缓存保持命中，明显降低长程多步任务的开销；新增按 provider 的请求频率上限，任务中途不再撞上服务商的限流；并在 Agent 回复下方加了一键问题回报。

## 支持侧边栏不可用的浏览器

有些 Chromium 浏览器提供了 Chrome 的 side panel API，却从不真的把面板显示出来——调用成功返回，界面上什么都没有。Pie 现在不再相信 API 的返回值，而是实测面板是否真的出现；没出现就把同一个面板改用独立窗口打开，贴在浏览器窗口右缘。

- **自动判定，也能手动指定** —— 检测到问题时 Pie 会自动切换。你也可以从扩展右键菜单或 **设置 → 在独立窗口中打开 Pie** 强制指定；你的选择永远优先于自动检测。
- **每个浏览器窗口一个面板**，面板失去焦点也不会中断正在运行的任务。
- **Chrome 上行为不变。**

## 长任务更省

长程任务此前会反复重发本可以走缓存的上下文。三处改动叠加，显著提升多步任务的缓存命中率：

- **提示缓存断点** —— 为 Anthropic wire 的几家 provider（Claude / DeepSeek / MiniMax / MiMo）标记缓存断点，重复上下文按缓存读取计费，而不是完整输入价。
- **删除滑动历史窗口** —— 从历史头部裁剪会让每一轮缓存全部失效，省下的 token 还不如多花的多。
- **页面读取瘦身** —— `read_page` 返回体此前大部分都花在可交互控件的标记上，现在体积大幅缩小，其后每一轮都跟着变轻。

## 请求频率上限

- **按 instance 配置每分钟请求上限** —— 在 instance 设置里填入你的服务商限额（留空表示不限）。达到上限时请求会**排队等待而不是直接失败**，聊天界面显示等待倒计时。
- **模型列表** 在 provider 设置中改为行卡形式，每个模型的信息更清晰。

## 聊天内回报问题

- Agent 最后一条回复下方出现回报图标，点开抽屉可以描述问题并连同整段会话一起发送——提示词、工具调用及其结果都在内，问题才真的能被追溯定位。
- **发送内容在抽屉里和 [PRIVACY.md](https://github.com/WiseriaAI/pie-ai-agent/blob/main/PRIVACY.md) 中均已写明**：transcript 包含 Agent 在任务中读过的页面正文。不点发送就不会有任何数据外发。
- 旧的 `report_issue` skill（引导你手动到公开 GitHub issue 里粘贴信息）已移除，由本功能取代。

## 上下文卡片改版

- **环上显示的是上下文大小，不再是成本。** 此前取的是 provider 原始 input token 数，而 Anthropic wire 家族的该字段**不含**缓存 token——缓存命中 90% 时，环只显示真实上下文的十分之一。
- **会话累计缓存命中率** 显示在总量下方。单轮比值有误导性：读页那一轮天然会掉下去，看着像坏了。
- **标题旁的说明** 解释了任务结束后上下文为什么会变短——中间过程被替换成了摘要。

## 修复

- **`open_url` 不再把跨 origin 重定向判为失败** —— apex 跳 `www` 这类服务端重定向（或任何落到不同 origin 的重定向）此前会被报成导航失败，尽管标签页已经正常打开，导致 Agent 无法 focus 该标签页。现在重定向会被正常跟随，按标签页实际落地的 origin 建立 pin，observation 里同时记录重定向的两端。
- **订阅到期后重新给出完整订阅引导** —— 订阅或兑换的权益到期后，设置页此前停在「暂无生效订阅」加一个直跳月付的按钮。现在会展示与新用户一致的月付／年付选择、首期优惠与兑换码入口。
